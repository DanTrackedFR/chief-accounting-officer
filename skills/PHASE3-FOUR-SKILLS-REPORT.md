# Phase 3 — four core accounting skills production handoff

All four packages have production contracts, governed reviewed-case workflows, deterministic workpapers, framework-specific routes, public-output integration and independent QA for their **supported scope**. This does not mean every accounting judgment is automated or every financial instrument/group transaction has a generic calculator. Complex matters have explicit specialist handoffs and return `blocked` until reviewed evidence and event-specific schedules are supplied. No skill is completed solely on the initial calculator tests.

## Execution and outputs

`production.assess_case` is the CAO-facing entrypoint; `execute` performs internal certification. `run_skill.py` is the public CLI. All seven public routes use `interfaces.public_output.public_record`: answer, answer context, retrieval snippet, citation, tool output, user log and export. Curated output includes the conclusion, numeric workpapers, journals, disclosure controls and substantive caveats; it excludes raw evidence/source notes/reviewer/hash objects. Contaminated output fails closed. Do not publish raw internal results.

The standard envelope separates facts, assumptions, conclusions, calculations, evidence, judgments, uncertainties and downstream controls/reporting/systems/documentation/audit consequences. Missing/invalid context or an unresolved specialist matter yields a structured blocked envelope, named specialist target and evidence/action requirements, without postable entries. Unapproved/stale case certification yields partial. Synthetic examples have clearly fictional data and review records; they are reproducible regression demonstrations, not real authorization.

Required context includes framework, jurisdiction, entity/period start/end, operative edition, adoption/elections, evidence and judgment memo. Canonical review hashes Markdown and claim-register content. Review selects actual applied claims and public caveats; unrelated claims do not become citations. Certification binds case data, canonical hashes and implementation bytes and requires an independent reviewer distinct from the preparer. It validates a supplied approval record, not reviewer identity or legal rights. The company must approve GL mapping and posting outside this read-only workpaper system.

GitHub CI uses the same skill, lease, repository and standards validation commands. The existing PR is moved to review after final synchronization to execute the full skill gate. The exact final commit must pass CI before integration; no merge is performed by this task.

## Authority, limitations and blockers

Approved claim evidence ratings and future direct-source assurance remain unchanged. A standard title is not a verified paragraph. Established pinpoint references retain their actual confidence; provisional references are labeled unverified, and missing pinpoints are not invented. The public caveat retains period/authority uncertainty without exposing internal source notes. The current FRC publication set and FASB CECL official materials were checked for contextual routing; this did not convert an ASU/overview into verification of operative Codification paragraphs.

The production status covers a bounded governed expert workflow using supported company facts and reviewed judgments. It does not include ERP posting, autonomous legal opinions, credit underwriting, valuation or completion of specialized subskills that belong to other canonical topics. These are explicit case-level boundaries rather than hidden default assumptions. Unresolved scope, missing source facts, failed reconciliation, stale approval or unresolved specialist evidence blocks that case. No unresolved demonstrated arithmetic/accounting defect remains in the supported tested routes after independent QA.

All work stays on `phase-3/four-core-accounting-skills` and PR13. Existing Phase2 knowledge, evidence tiers, canonical tracking and the Lease Accounting skill are preserved. PR13 remains unmerged pending integration review and final green CI.
