# TOPIC-12-006 — Journal Entry Operating Model / Accounting Process Documentation

Status: REVIEWED / production-candidate
Primary capabilities: CAO-12-015, CAO-12-016

## Objective
Make journals controlled accounting outputs and process documentation executable operating knowledge rather than retrospective prose.

## Journal operating model
Classify journals as source-system automated, recurring, allocation, accrual/estimate, reclassification, consolidation/elimination, correction or exceptional/manual. For each class define permitted preparers, approval thresholds, required support, posting source, reversal logic, period access and monitoring.

Every journal should identify entity, period, accounts/dimensions, currency, debit/credit, purpose, source/calculation, preparer, approver, posting ID and—where applicable—reversal/reference to originating case. Unsupported descriptions such as 'true-up' are insufficient.

High-risk indicators include unusual users/times, manual postings to system-controlled accounts, round amounts, late/post-close entries, entries just below approval thresholds, unusual combinations, repeated reversals and senior-user self-posting. Indicators trigger review; they do not prove error or fraud.

## Documentation model
A useful accounting process narrative records objective, scope, trigger, inputs, authoritative accounting dependencies, systems, roles, steps, decision points, outputs, controls, evidence, exceptions, reconciliations, close timing, upstream/downstream dependencies and change ownership. Link Policy → Process → System → Control → Accounting Result.

## Controls
Role segregation; workflow approval; posting rights; period locks; recurring-template governance; automated-journal configuration control; completeness/control totals; manual journal analytics; post-close review; evidence retention; versioned process documentation and periodic owner certification.

## Artifacts
Journal policy/matrix; JE support pack; recurring-journal register; manual-JE exception report; process narrative; RACI; system/control map; change log.

## Scenarios
Recurring accrual template continues after contract ends: template owner must revalidate source/period, not rely on prior approval. Automated interface journal changes after ERP release: treat configuration as accounting change and revalidate totals/mapping. Emergency post-close correction: preserve approval, reason, impacted reporting and reopen history.

## Completion criteria
CAO can select the right journal route, demand sufficient support, design preventive/detective controls, identify risky patterns, and document an accounting process so another professional can operate and audit it.
