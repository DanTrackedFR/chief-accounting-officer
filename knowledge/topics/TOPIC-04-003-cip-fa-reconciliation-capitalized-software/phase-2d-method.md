# Construction in progress, register bridge and software transfer

Companion to `knowledge-pack.md` and the 100,000 CIP example. CAO-04-007–009. Recognition belongs to the appropriate tangible or software topic, not the existence of a project code [04-003-IFRS-01; 04-003-US-01].

## Framework routing

Tangible construction under IAS 16/AASB 116 and FRS 102 Section 17 accumulates only qualifying costs while the asset is being readied. Depreciation begins when it is capable of intended use, even if a project manager has not closed the budget. Separately review interest, restoration and impairment; an aged project can have an impairment indicator before service. UK 2026 edition and Australian period/tier gates apply [04-003-IFRS-01; 04-003-AASB-01; 04-003-UK-01]. US tangible construction routes to ASC 360, with capitalized interest where ASC 835-20 applies; software development must be separately classified as internal-use ASC 350-40, external-sale ASC 985-20 or hosted-service implementation under the appropriate US model. The software capitalization gate and 2025-06 future amendment are detailed in 04-004 [04-003-US-01; 04-003-US-02]. No framework treats an unapproved time allocation or a vendor's label as proof of qualifying asset cost.

## Control-total bridge and posting

For project P, opening CIP 200,000 + accepted vendor cost 120,000 + qualifying time 80,000 − ready portion 300,000 = closing CIP **100,000**. Current postings Dr CIP 200,000 / Cr AP/payroll 200,000; commissioned portion Dr PPE 300,000 / Cr CIP 300,000. A later discovery that 20,000 of payroll was training changes current qualifying additions to 180,000 and closing CIP to 80,000 *unless* the 300,000 transfer included that ineligible cost, in which case correct the transferred asset too. This adverse case prevents a balanced but wrong rollforward [04-003-IFRS-01; 04-003-US-01].

Use a project-to-asset bridge with project ID, legal entity, framework, source invoice/time entry, service date, capitalization reason, status/commissioning evidence, asset/component ID, gross cost, accumulated depreciation and GL journal ID. Reconcile project population to AP/payroll/GL completeness, CIP to class and asset ID, and fixed-asset register gross and accumulated balances independently to GL. One project may produce several assets with different ready dates. Include not-ready assets in impairment/abandonment review; separate product software from machinery control code. Expense a terminated project under the applicable impairment/derecognition route rather than leaving an indefinite CIP balance [04-003-IFRS-01; 04-003-US-02].

Fail cases: (1) a July commissioning acceptance omitted from August transfer; post transfer and catch-up depreciation from actual readiness; (2) subledger net carrying agrees but gross cost is 50,000 high and accumulated depreciation 50,000 high; fail both gross control totals; (3) user has access only to a SaaS service; no customer-controlled intangible from a project budget alone; (4) 2028 US internal-use project uses pre-2025-06 staging without adoption/transition review; fail. Notes reconcile gross additions/transfers, depreciation and impairment by class; Tier 2 Australian disclosure uses AASB 1060 [04-003-US-02; 04-003-AASB-01].
