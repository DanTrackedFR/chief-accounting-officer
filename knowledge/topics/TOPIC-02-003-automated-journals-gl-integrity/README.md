Canonical topic ID: TOPIC-02-003. Capabilities: CAO-02-007 (recurring/automated journal design), CAO-02-008 (GL integrity review). Status proposed: worker QA candidate; canonical promotion belongs to independent integration. This directory is the proposed entrypoint because it has the substantive `factory.md`, `knowledge-pack.md`, [`methods/automated-posting-contract.md`](methods/automated-posting-contract.md) and [`tests/phase-2d-worker-scenarios.md`](tests/phase-2d-worker-scenarios.md).

The alternate [`TOPIC-02-003-recurring-journals-gl-integrity`](../TOPIC-02-003-recurring-journals-gl-integrity/README.md) contains useful recurring-journal eligibility and GL integrity tests. Read both packs; the alternate is not another canonical topic. Before any automated posting, prove source completeness, approved policy/rule, rule version, entity/book/period mapping, exception queue, idempotency, independent approval and GL reconciliation. A recurring template without a current underlying transaction or obligation must not run merely because it ran last month. An automated batch can balance while duplicating an earlier run or losing rejected rows.

CAO output: automated-journal specification, source-to-accepted/rejected-to-posted bridge, access/change log, exception/retry and reversal plan, GL anomaly review, signed close evidence. For a timeout, query destination IDs before retry. The 1,000-record example in the method requires 996 accepted/99,600 and four rejects/400 to remain visible; a second 99,600 batch fails. Underlying recognition/measurement belongs to the applicable technical topic. Dependencies: TOPIC-02-002, 09-003, 11-003/010 and 12-006. No artificial framework differences are asserted for the mechanics of a journal workflow.
