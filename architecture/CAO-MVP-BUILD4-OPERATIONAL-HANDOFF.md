# Post-Build 4 operational and MVP acceptance

Engine engineering acceptance is bounded deterministic synthetic-source execution
through actual local/hosted interfaces and native production owners. Controlled
interpretation remains inferred. Synthetic test reviewers are not authenticated
humans. The final source SHA/check receipts are in the sole Build4 PR; do not merge
from an older gate or regenerate historical references to conceal differences.

Before commercial release require owner review/integration, TrackedFR Build2B real
Express→Python acceptance, live-model conversational evaluation and actual Claude
Code user smoke. Production sources need independently qualified owner inputs and
standards/effective-period assurance; APPROVED topics don't imply SOURCE_VERIFIED.

Deploy on one protected POSIX host with durable local SQLite disk and one job worker.
Verify TLS/reverse-proxy request/header/time/rate controls, company access, scoped
service credential rotation, authenticated accounting roles/separation, audit logging,
backup restore/retention, data protection, monitoring/alerting, incident runbooks,
capacity/load and upgrades with retained Case/version receipts. These are operational
acceptance dependencies, not newly implemented infrastructure or unsolicited gates.

Supported document parsing is bounded and inert; OCR, spreadsheet recalculation,
general arbitrary-prose accounting-input qualification, external posting, ERP/Drive
connectors, MCP and multi-host/distributed transaction guarantees remain absent.
Governed memory is exact-version context only, with native consumption receipts and
currentness checks; it cannot replace qualified owners. Retired/conflicting/stale
positions and unknown dates must remain visible/refused.

Government Grants #34, Borrowing Costs #35 and Investment Property #37 continue under
separate management. Current metadata/production gates control blocked availability.
Do not begin those workstreams or TrackedFR implementation from this release.
