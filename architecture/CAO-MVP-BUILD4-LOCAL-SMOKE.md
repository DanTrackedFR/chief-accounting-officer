# Local Claude Code operator smoke — not an executed user smoke

Use Python3.12+ on POSIX and a private local workspace with persistent disk.
Install `intelligence/requirements.txt` and clone the reviewed release SHA.
Read CLAUDE.md, docs/LOCAL-CAO.md and the three interfaces/CAO-*-CONTRACT.md
files. Provision company-context.md from company-context.example.md with
actual company/entity/framework/calendar/period/functional/presentation currency.
Unknown facts stay UNKNOWN; labels do not approve policies.

1. Through Claude Code invoke `python -m local_cao --workspace PRIVATE_PATH`
   with shared1.0 initialize, diagnose and capabilities JSON. Check actual owner
   availability, not skill naming or model confidence.
2. Ask a new natural-language accounting question. Supply controlled interpretation
   through the validated family/claims/questions boundary. Preserve exact source
   fields and uncertainty; model observations are not accounting facts.
3. Investigate and show the requested executed agreement or comparative/current
   reconciliation. Ingest a bounded supported document envelope naming exact
   company/entity/period/currency and immutable document version. Show parser warnings.
4. Follow evidence requests by actual transaction source ID. Ask the source-linked
   follow-up. Obtain an independently reviewed native intake pack; never ask Claude
   to manufacture reviewer seals. Submit and execute through the same interface.
5. Inspect accounting execution_state, currentness, open_items and limitations.
   Render only public_result for accounting; investigation observations are separate.
6. Restart the actual client process and resume the same Case. Retry the unchanged
   request, then a reviewed successor source via correct_investigation and
   rework_investigation. Compare retained versions and exact journal economics.
7. Record client/version/model/provider, actual source IDs, Case IDs and outcomes.
   A live Claude Code smoke PASS requires actual user/client operation and cannot
   be inferred from deterministic CLI subprocess tests.

Build4 tests exercise the production CLI and controlled interpretation, not a live
Claude Code session. Live model credentials/production sources/authenticated reviewer
approval remain separate operational acceptance gates.
