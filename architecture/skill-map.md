# Complete CAO Skill Map — v1

This is the Phase 1 capability taxonomy. It defines **what capabilities must exist**, not their accounting content. Each capability will later become a governed Skill package or, during implementation review, a deliberately merged sub-capability. IDs are stable design identifiers.

A skill has one primary domain. Cross-domain dependencies are handled by orchestration and metadata, not duplication.

## Taxonomy review rules

Before production build, every skill MUST be tested for:
- distinct objective;
- clear trigger/non-trigger;
- sensible primary domain;
- no duplicate capability elsewhere;
- appropriate granularity for orchestration;
- framework/jurisdiction/industry sensitivity;
- required context;
- expected artifacts and completion criteria.

The map is deliberately broad enough to represent a complete CAO remit. Phase 3 may merge or split skills when reference-skill testing proves that orchestration quality improves, but such changes MUST preserve traceability from this map.
